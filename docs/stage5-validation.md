# Этап 5 — живая валидация Исполнятора

Фиксирует реальную проверку Исполнятора в реальном приложении на реальных данных владельца, а не только
тесты. Модель и решения — ADR-0006. Пути к данным, секреты, приватный iCal-адрес и идентификаторы машины
здесь намеренно не приводятся.

## Gate A — решения владельца

Потеря фокуса / свёрнутое окно — таймер идёт. Выход из приложения и сон ОС — пауза, без автопродолжения.
Сбой — закрытие по последнему checkpoint. «Готово» во время работы — одно атомарное действие. Ручного
редактирования времени нет.

## Gate B — визуальная проверка

Владелец принял UI таймера внутри `Сейчас`. Реальное действие для проверки пришло обычным путём — через
AI Proposal (`4b092a12`, принят владельцем): «Прожить реальный рабочий цикл через Исполнятор» в текущем
этапе «Добавить Исполнятор». На Gate B владелец также запросил доработки видимости экрана Proposal и
свёрнутую историю / логику плана — они одобрены как часть Этапа 5.

## Независимый review

Opus-review всего diff Этапа 5: 0 HIGH, 2 MEDIUM, оба исправлены до Gate C.

- **M1 — незамеченный сон.** Если событие `suspend` не пришло, открытый интервал мог досчитать время сна.
  Исправлено: интервал с checkpoint старше `WORK_HEARTBEAT_GAP_MS` (3 мин) считается «молчащим» и везде
  обрезается по последнему checkpoint (`isSilent` / `closeAt` в `packages/domain/src/work.ts`): в чтениях,
  контексте ИИ, при «Пауза» / «Готово» / «Продолжить»; `powerMonitor` `resume` / `unlock-screen` сразу
  закрывают такой интервал.
- **M2 — второй процесс.** Второй запуск мог «восстановить» идущую работу первого. Исправлено:
  `app.requestSingleInstanceLock()`; при переопределённом `LIVING_MAP_HOME` `userData` лежит внутри него.

## Gate C — реальный рабочий цикл

Реальное приложение, реальная БД владельца (часовой пояс Asia/Jakarta):

1. **Начать** → таймер действия пошёл; дневной и недельный счётчики растут.
2. **Пауза** → время остановилось. **Продолжить** → новый интервал, сумма действия продолжилась.
3. **Выход из приложения** во время работы → пауза записана (`work.pause`, actor `system`).
   **Перезапуск** → восстановлено состояние «на паузе»; время между выходом и запуском не посчитано.
4. **Сон ОС** во время работы → пауза записана (`system`); время сна не посчитано.
   После пробуждения автопродолжения нет; **Продолжить** сработало.
5. **Готово** во время работы → время остановлено и действие завершено одной командой (одна ревизия).

Четыре рабочих отрезка по действию: закончились соответственно ручной паузой, выходом из приложения, сном
ОС и «Готово».

## Известные ограничения (LOW, приняты)

- Выключение Windows может обойти корректную паузу при выходе; восстановление обрезает интервал по
  последнему checkpoint, так что неточность — примерно один интервал heartbeat.
- Скачок системных часов назад может дать недосчёт, но никогда — отрицательную работу.
- Изменения исполнения увеличивают `state_revision`, поэтому ИИ может понадобиться перечитать контекст.
- Dev-сборка и упакованное приложение не должны намеренно работать одновременно с одной реальной папкой данных.
- Внешний MCP-host может потребовать переподключения / перезапуска после обновления схемы или кода.
