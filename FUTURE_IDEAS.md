# Живая карта — отложенные идеи

Идеи, которые появились по ходу работы, но не нужны для Definition of Done текущего этапа (CLAUDE.md §4). Не план и не обязательство.

## Из Этапа 3 (ИИ-мозг через MCP)

- **Per-action «почему сейчас» в OrderedActionPlan.** Стратегическая причина для каждого действия (ARCHITECTURE §28). Нужна, когда появится `Сейчас` (Этап 4).
- **Proposal на изменение сезона и «Чем ты не хочешь жертвовать ради целей?».** Сейчас у ИИ нет никакого пути менять их — только сказать пользователю словами.
- **Блокировки и удаление/объединение действий в маршрутном Proposal.** Сейчас маршрут умеет только добавлять и править (без удаления и без смены статусов).
- **Ручное редактирование плана пользователем в UI.** Сейчас порядок меняет только ИИ (через Proposal или безопасную перестановку).
- **Более точный признак устаревания.** Сейчас любое изменение планировочного контекста делает Proposal устаревшим; можно сузить до реально затронутых сущностей, если это начнёт мешать на практике.

## Из Этапа 7 (Разборы и обучение на прожитом)

- **Прямая связь ReviewFinding → Proposal.** Сейчас `suggestion` в находке — только текст для пользователя; ревью-задача ИИ не имеет доступа к MCP и не может сама создать Proposal. Пользователь должен сам поднять предложение через `+`.
- **Ручное редактирование текста Pattern-кандидата.** Сейчас только «Сделать правилом» / «Не считать правилом», без правки формулировки перед подтверждением.
- **Семантическое сопоставление находок без `patternKey`.** Сейчас Pattern candidate возникает только по точному совпадению слага, который сам придумал ИИ — без эмбеддингов/похожести текста.
- **YearlyReview с полноценным сравнением траектории.** Требует `LifeDirection`/дальних горизонтов Этапа 8; пока год анализируется той же evidence-моделью, что и остальные типы разборов.
- **Evidence завершения действия из `change_log`, а не из `completedAt`.** Переоткрытие/повторное завершение действия до разбора периода может убрать факт из evidence того периода (независимое ревью, M7).
- **Evidence pack по снимку на момент `claim`, а не пересборка при `finishReview`.** Сейчас пересборка = проверка по актуальной правде ценой редкого `malformed` при реальном изменении данных между claim и finish (независимое ревью, M7).
- **Структурированное evidence для weekly/seasonal:** зависшие Замыслы без активности, рабочая ёмкость против нормы — сейчас только текстовая разница промпта по типу и перенесённые темы `patternKey` (независимое ревью, M8).
- **Явное подтверждение владельцем provenance интерактивно связанной Memory (M-A, путь Б).** Сейчас связь Memory↔Capture, сделанная ИИ из интерактивной/чат-сессии (без `ctx.captureId`), сохраняется как Stage-6-ассоциация, но никогда не становится verified provenance для независимости Pattern сама по себе — только доверенный запуск обработки самой Capture это может. Владелец мог бы сам подтвердить «да, эта Memory действительно из этой Capture» и тем самым явно повысить связь до verified; отдельная UI-функция, не инвариант, не реализована.
